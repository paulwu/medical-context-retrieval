## Summary

### Problem
Azure Policy enforces `disableLocalAuth = true` on the existing `SharedAIFoundry` Cognitive Services account. Terraform's `listKeys` API call fails with `400 Bad Request` because key-based authentication is disabled.

### Root Cause
Three `azapi_resource_action` data sources called `listKeys` unconditionally:
- `existing_ai_foundry_account_keys_default` (main.tf)
- `existing_ai_foundry_account_keys_subscription` (main.tf)
- `ai_foundry_account_keys` (modules/ai_foundry/outputs.tf)

### Fix Applied (6 files changed)
1. **variables.tf** — Added `existing_ai_foundry_local_auth_disabled` variable
2. **main.tf** — Gated both `listKeys` data sources with `&& !var.existing_ai_foundry_local_auth_disabled`
3. **main.tf** — Updated `existing_ai_foundry_account_key` local to return `null` when local auth disabled
4. **main.tf** — Updated `azurerm_key_vault_secret.azure_openai_api_key` count to skip when local auth disabled
5. **main.tf** — Relaxed `azure_openai_key_supplied` check when using Managed Identity
6. **modules/ai_foundry/variables.tf** — Added `disable_local_auth` variable
7. **modules/ai_foundry/main.tf** — Wired `disableLocalAuth` to use the variable
8. **modules/ai_foundry/outputs.tf** — Gated `listKeys` and key output on `!var.disable_local_auth`
9. **terraform.tfvars** — Set `existing_ai_foundry_local_auth_disabled = true`

### Result
`terraform plan` completes successfully. When local auth is disabled, the infrastructure relies on RBAC/Managed Identity authentication instead of API keys.
