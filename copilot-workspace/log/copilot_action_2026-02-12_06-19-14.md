**Request:** Fix DevContainer rebuild error

## Root Cause Analysis

**Issue:** DevContainer rebuild fails due to two problems:

1. **Stale Yarn GPG key in base image:** The base image `python:1-3.11-bullseye` ships with `/etc/apt/sources.list.d/yarn.list` referencing keyring `/usr/share/keyrings/yarn-archive-keyring.gpg`. The Dockerfile attempted to remove `yarn-keyring.gpg` (wrong filename) instead of `yarn-archive-keyring.gpg`.

2. **Debian Bullseye End of Life:** Debian 11 (Bullseye) is EOL. DevContainer feature installations (azure-cli, terraform) may fail on this outdated base OS due to unsupported package managers or missing dependencies.

**Evidence:**
- `docker run` against base image → `E: The repository 'https://dl.yarnpkg.com/debian stable InRelease' is not signed` (NO_PUBKEY 62D54FD4003F6525)
- Actual keyring file: `/usr/share/keyrings/yarn-archive-keyring.gpg` (Dockerfile removes wrong path)
- Current running container: Ubuntu 24.04 / Python 3.12 (not from this Dockerfile)

---

## Action Plan

1. [x] Update Dockerfile: change base from `python:1-3.11-bullseye` to `python:1-3.12-bookworm`
2. [x] Fix yarn keyring removal to use correct filename and glob pattern

## Changes Made

### `.devcontainer/Dockerfile`

| Before | After |

## Summary

DevContainer rebuild was failing due to two compounding issues:

1. **Wrong yarn GPG keyring filename** — Dockerfile removed `yarn-keyring.gpg` but the base image contains `yarn-archive-keyring.gpg`. Fixed with a glob pattern `yarn*.gpg`.

2. **Debian Bullseye (11) is End of Life** — Feature installations (azure-cli, terraform) can fail on EOL distributions. Upgraded to Bookworm (Debian 12) with Python 3.12.
