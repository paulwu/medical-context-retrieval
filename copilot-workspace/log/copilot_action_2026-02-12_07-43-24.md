## Root Cause

The container builds and starts successfully, but the **WSL2 host shell terminates** after ~13.5 seconds with exit code 0. This kills all `docker exec` sessions running through it (keep-alive, env probe, setup), causing the `unexpected end of parent stream` error cascade.

**Docker daemon confirmed the same issue:**
```
exec attach failed: error attaching stdout stream: write: broken pipe
copy stream failed: io: read/write on closed pipe (stdin)
```

The container's PID 1 (started via `docker run ... -c echo Container started`) exits immediately, leaving the container alive only as long as `docker exec` keep-alive sessions persist. When the WSL shell drops, those exec sessions die, and the container stops.

## Summary

The DevContainer rebuild was failing due to the WSL2 host shell connection dropping during container setup, killing all `docker exec` sessions. The container had no long-running PID 1 process, so it died immediately when the keep-alive exec session was lost.

**Fix:** Added `ENTRYPOINT ["sleep", "infinity"]` to the Dockerfile and `"overrideCommand": false` to devcontainer.json. This ensures the container stays alive independently, surviving WSL connection interruptions. Docker daemon was restarted to clear stale state.

**Next step:** Rebuild the Dev Container from VS Code (Ctrl+Shift+P → "Dev Containers: Rebuild Container").

**If the error persists:** Run `wsl --shutdown` from Windows PowerShell, then reopen VS Code. This resets the WSL2 VM and clears any networking/pipe issues.
