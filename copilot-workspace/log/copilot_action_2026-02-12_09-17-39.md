## Findings

### Root Cause
The Dev Container build **failed at step 6/6** — installing the **Terraform feature** (`ghcr.io/devcontainers/features/terraform:1`).

**Error chain:**
1. The Terraform feature install script runs `apt-get update`
2. The base image (`mcr.microsoft.com/devcontainers/python:1-3.11-bookworm`) includes a stale Yarn APT source with an expired/missing GPG key:
   ```
   Err:5 https://dl.yarnpkg.com/debian stable InRelease
     The following signatures couldn't be verified because the public key is not available: NO_PUBKEY 62D54FD4003F6525
   ```
3. This causes `apt-get update` to fail with:
   ```
   E: The repository 'https://dl.yarnpkg.com/debian stable InRelease' is not signed.
   ```
4. The Terraform feature treats the apt failure as fatal → **exit code 100**

### Impact
The container cannot be built/rebuilt. The `--build-no-cache --remove-existing-container` flags suggest the user triggered a full rebuild which then failed.

---

## Fixes (in order of preference)

### Fix 1: Remove or disable the stale Yarn source before features install (Recommended)
Add an `initializeCommand` or `onCreateCommand` that removes the problematic Yarn APT list, or add an `overrideFeatureInstallOrder` with a custom pre-step.

Simpler approach — add a Dockerfile that cleans up the Yarn repo before features run:

**Create `.devcontainer/Dockerfile`** with:
```dockerfile
FROM mcr.microsoft.com/devcontainers/python:1-3.11-bookworm
RUN rm -f /etc/apt/sources.list.d/yarn.list && apt-get update
```

Then update `devcontainer.json` to use `"build": { "dockerfile": "Dockerfile" }` instead of `"image"`.

### Fix 2: Pin the Yarn GPG key
Import the new Yarn signing key before the feature installs. This is fragile if the key changes again.

### Fix 3: Use `containerEnv` to set `DEBIAN_FRONTEND=noninteractive` and a custom `initializeCommand`
The simplest one-line fix: remove the yarn source file before build.

## Summary

- **Single root cause:** Stale Yarn GPG key (`NO_PUBKEY 62D54FD4003F6525`) in the base Python devcontainer image causes `apt-get update` to fail, which causes the Terraform feature install to abort with exit code 100.
- **Recommended fix:** Switch from `image` to a custom `Dockerfile` that removes the Yarn apt source before features are installed. Applied to `devcontainer.json` and new `Dockerfile` created.
