### How mirrored networking causes the crash

1. `networkingMode=mirrored` replaces WSL2's default NAT network stack with a shared-host-interface mode
2. This mode is **experimental on Windows Insider builds** and has known stability issues with Hyper-V socket (HvSocket) connections
3. VS Code communicates with WSL2 through HvSocket pipes: `wsl.exe` → HvSocket → WSL2 VM → `/bin/sh`
4. The mirrored network driver's instability causes the HvSocket pipe to break after ~14 seconds
5. The `/bin/sh` shell sees EOF on stdin → exits cleanly (code 0)
6. All `docker exec` sessions running through that shell die simultaneously → **"unexpected end of parent stream"**

### Why previous fixes didn't work

All 9 previous sessions modified DevContainer config (`devcontainer.json`, `Dockerfile`, `setup.sh`), Docker state, or process cleanup. **None of these could fix a WSL2 kernel-level networking issue.** The Docker image builds correctly, the container starts correctly, and VS Code's setup commands run correctly — until the HvSocket pipe breaks.

## Summary

After 10 sessions of debugging, the root cause was identified as **`networkingMode=mirrored` in `.wslconfig`** combined with a **Windows Insider Preview build (26200)**. The mirrored networking mode destabilizes HvSocket connections between VS Code and WSL2, causing the communication pipe to break after ~14 seconds. This kills the parent WSL shell and all Docker exec sessions, producing the "unexpected end of parent stream" error. Changing to NAT mode (the stable default) should resolve the issue. A `wsl --shutdown` from Windows PowerShell is required for the change to take effect.
